# 票务自动经营控制台 UI / 产品设计

**产品需求基线：** `docs/prd/2026-07-30-ticket-automation-platform-v1-prd.md`

## 1. 设计目标

控制台不是后端资源的 CRUD 外壳，而是业务用户监督自动经营、理解证据链并处理例外的工作台。用户每天首先需要知道：完整自动化是否可用、当前是否接单、系统正在处理什么、哪些问题必须由自己决定，以及今天完成了多少业务。

本设计覆盖三个界面，但职责不同：

- Web 控制台：完整经营、订单旅程、恢复任务和经营设置。
- Chrome 扩展 Popup：激活登录、当前闲鱼页面和账号状态、即时运行控制，以及跳转控制台。
- 现有 `xianyu-manual.html`：能力迁入订单中心后下线，不维护第二套人工处理 UI。

首版以桌面端为主要操作环境。平板将双栏折叠为上下结构；手机端支持查看待办、订单证据和单项紧急处理，但复杂配置、批量操作与规则编辑引导至桌面端。

## 2. 角色与隐私边界

### 2.1 业务用户

业务用户管理自己的闲鱼经营账号、订单旅程、执行授权、良票账号、营业时间、话术、定价和通知。所有业务数据必须由当前 `userId` 限定。

### 2.2 管理员

管理员只管理：

- 创建、停用和恢复业务用户；
- 重置用户初始密码；
- 审批、拒绝、续期和吊销插件或机器人 Token；
- 用户治理与授权审计。

管理员不能查看或搜索：报价、订单、买家、闲鱼账号、金额、利润、票码、良票用户名、上游业务订单或业务通知。Token 明文只在业务用户创建后展示一次，管理员只能看到前缀。现有 `/api/v1/admin/orders` 与该边界冲突，实施时必须删除或封闭。

## 3. 产品原则

1. **例外优先**：首页先展示恢复任务和订单任务，再展示进行中订单与轻量经营结果。
2. **订单聚合**：Xianyu Platform Order 是订单中心主对象；本地出票订单是旅程中的一个履约阶段。
3. **证据优于推断**：每个状态展示来源、时间和下一步；未知结果不展示为失败或成功。
4. **业务语言优先**：列表使用待付款、验款、出票、待发货、已完成、需要处理，不直接暴露内部枚举。
5. **安全动作明确**：首页只分流；有业务后果的操作进入订单详情，并只提供任务类型允许的动作。
6. **真实状态驱动**：首次向导、自动化就绪与恢复检查读取后端持久状态，不使用前端勾选或模拟指标。
7. **默认配置、显式覆盖**：业务用户拥有默认话术、定价等配置，单个闲鱼经营账号可以显式覆盖。

## 4. 信息架构

### 4.1 业务用户一级导航

```text
今日
订单中心
经营数据
自动化
经营设置
```

账号安全进入右上角个人菜单，不占一级导航。顶栏包含：账号范围选择器、接单状态操作、通知中心、命令面板入口和用户菜单。账号范围默认为“全部闲鱼账号”，选择单账号后影响今日、订单、数据、自动化和经营设置；客户端授权、良票账号和账号安全不随范围变化。

### 4.2 管理员一级导航

```text
待审批
用户与授权
治理审计
```

管理员没有业务工作区入口，也不能通过 URL、API 或全局搜索进入用户业务数据。

## 5. 核心页面

### 5.1 今日：运营收件箱

```text
┌──────────────────────────────────────────────────────────────┐
│ 全部闲鱼账号 ▾    自动化就绪 · 正常接单     [停止全部接单] │
│ 接待 ●  报价 ●  验款 ●  出票 ●  发货 ●                    │
└──────────────────────────────────────────────────────────────┘

┌──────────────── 恢复任务 ────────────────┐
│ 当前无恢复任务 / 能力故障与恢复步骤       │
└───────────────────────────────────────────┘

┌──────────────── 订单任务 ────────────────┐
│ 金额不一致、结果未知、出票或发货异常       │
│ 每项只提供“查看并处理”                     │
└───────────────────────────────────────────┘

┌──────────────── 正在处理 ────────────────┐
│ 待付款 8 · 验款 2 · 出票中 5 · 待发货 1  │
└───────────────────────────────────────────┘

┌──────────────── 今日经营 ────────────────┐
│ 已收款 8 单 / ¥486.20                    │
│ 已完成 6 单 / ¥371.80                    │
│ 已实现利润 ¥42.60 · 自动完成率 94.2%     │
└───────────────────────────────────────────┘
```

恢复任务与订单任务是两套队列。通知“已读”不解决任务；任务只有完成合法动作或得到恢复证据后才解决。任务允许受约束地“稍后提醒”，但仍是待处理状态，高风险任务受最长暂缓时间和 SLA 约束。

### 5.2 订单中心

默认筛选和排序：

```text
全部 | 需要处理 | 待付款 | 验款 | 出票中 | 待发货 | 已完成
```

优先级依次为需要处理、即将超时、最近更新的进行中订单、已完成订单。每行显示：闲鱼经营账号、电影与场次、买家脱敏标识、金额、当前业务阶段、下一步、最后更新时间。内部状态只出现在诊断详情。

报价记录是订单中心的次级视图，用于查询尚未形成 Xianyu Platform Order 的报价；本地出票订单不再作为一级列表，而在订单详情中展示。

### 5.3 订单详情

```text
┌──────────────────────── 订单摘要 ─────────────────────────┐
│ 电影 / 影院 / 场次 / 座位   买家   经营账号   金额与利润 │
└────────────────────────────────────────────────────────────┘

┌──────────────────────────────┬─────────────────────────────┐
│ 票根旅程                     │ 当前决策面板                │
│ ✓ 图片报价  ¥58.38           │ 实付金额不一致              │
│ ✓ 待付款订单已登记           │ 报价  ¥58.38                │
│ ✓ 闲鱼改价  ¥58.38           │ 改价  ¥58.38                │
│ ! 实付验证  ¥56.38           │ 实付  ¥56.38                │
│ ○ 上游出票                   │ 差额  -¥2.00                │
│ ○ 闲鱼发货                   │ [标记已退款] [关闭订单]     │
└──────────────────────────────┴─────────────────────────────┘
```

右侧只展示当前 Order Task 允许的业务动作。每个 Manual Decision 必填说明并记录操作人、时间和证据。原始协议、内部枚举、诊断 ID 和技术错误放在折叠诊断区。

### 5.4 自动化

自动化页以闲鱼经营账号运行卡为主，不以 Token 表为主：

```text
影票小店 A                                      正常接单
接待 ●  报价 ●  验款 ●  出票 ●  发货 ●

执行授权     tk_a81f... · 2026-12-31 到期
运行客户端   办公室 Chrome · WebSocket 在线
闲鱼页面     已连接 · 当前账号匹配
营业时间     09:00–22:00
良票账号     LP-01 · 检查通过
话术         继承默认 v5
定价         自定义 v3

[停止接单] [更换执行 Token] [查看诊断]
```

一个闲鱼经营账号同时只能有一个 Execution Authorization。有效且空闲的 Token 可授权另一个账号。新 Token 接管时后端原子替换执行代次，旧执行者立即失效；账号历史、配置和统计不变。安全订单继续，外部结果未知的具体订单进入 Order Task。

### 5.5 经营设置

- **接单与营业时间**：每周七天、每天最多两个时段、允许跨夜、禁止重叠，使用业务用户配置的时区。
- **停止接单话术**：无未完成 Accepted Order 的会话在一个 Closed-Intake Period 内最多回复一次；不 OCR、不报价。
- **自动回复**：可视化编辑普通接待、订单阶段、停止接单和异常话术；受控变量由按钮插入，未知变量保存失败；JSON 只用于高级导入导出。
- **定价策略**：草稿、实时试算、边界校验和发布；历史报价引用不可变版本，发布只影响新报价。
- **良票账号**：凭据不回显；多个闲鱼账号可共享一个良票账号，但每个账号必须显式绑定，订单接受时固定引用，系统不自动切换。
- **默认与覆盖**：显示“继承默认 vN”或“账号覆盖 vN”，允许一键恢复继承。

### 5.6 首次启用向导

向导可中断恢复，并以真实状态判断完成：

```text
创建 Token → 等待审批 → 激活插件 → 识别闲鱼账号
→ 绑定良票账号 → 设置接单规则 → 发布定价
→ 安全演练 → 开始接单
```

安全演练完成前保持停止接单且不触发真实出票。新增第二个账号使用精简流程并复用用户默认配置。

### 5.7 管理员用户主档

管理员不在用户表与 Token 表之间跳转。用户详情聚合账号状态、最近登录、密码状态、Token 前缀、审批状态、有效期、客户端授权状态和治理审计，但不出现闲鱼账号名称或任何业务内容。

审批动作是“批准并选择 30/90/180 天或自定义期限”或“拒绝”。拒绝为终态，用户必须创建新申请。首版不设置 Token 数量硬配额，只显示同类有效授权数量和近期申请频率。

## 6. 接单与自动化规则

### 6.1 停止接单

待付款订单成功持久化是 Accepted Order 截止点。停止接单后：

- 不处理新截图、不调用 OCR、不生成新报价；
- 未完成 Accepted Order 的会话继续订单阶段回复和完整履约；
- 其他会话继续普通聊天策略，但一个停止时段只发送一次下班回复；
- 已开始且结果未知的外部动作仍禁止重放。

顶栏和今日页都可停止接单。全部账号视角按钮写“停止全部接单”，单账号视角只影响当前账号。确认面板显示影响范围、已接受订单数量和停止原因。恢复前必须通过完整就绪检查。

### 6.2 Automation Readiness

总状态由五段业务能力与底层证据共同决定：

```text
接待 → 报价 → 验款 → 出票 → 发货
```

底层证据包括执行授权、插件 WebSocket、闲鱼页面、闲鱼登录账号、OCR/报价能力、良票账号、凭据解密、持久任务队列和发货协议。关键能力故障触发 Readiness Stop；恢复后显示“可以恢复”，由用户确认接单。Web 控制台自身的实时连接中断只影响实时刷新，不代表插件或自动化离线。

### 6.3 WebSocket 控制面

允许消息：实时 presence、结构化能力状态、状态变化通知、请求重新上报、刷新已发布配置、停止/恢复接单。禁止远程触发改价、下单、付款验证、发送票码或发货。所有消息严格校验类型、代次和用户/账号归属；未知消息立即失败。

## 7. 统计口径

- **已收款**：以实付验证通过时间统计。
- **已完成**：以闲鱼发货成功时间统计。
- **预计利润**：报价时计算。
- **已实现利润**：发货成功后计入；退款和发货结果未知不计入。
- 单账号按账号时区；全部账号视角按业务用户默认时区。
- 首期首页只做轻量指标；独立经营数据页后续提供日期范围、转化率、平均出票时间、自动完成率、异常原因和账号对比。

## 8. 通知与搜索

业务通知渠道：站内通知、活动插件的浏览器系统通知、可选微信机器人通知。同一事件只产生一条可更新通知；通知点击进入任务或订单。用户可调整渠道，但自动停止接单、金额异常和结果未知等高风险事件不能完全关闭。

管理员只接收用户治理和 Token 审批通知。业务用户与管理员使用完全隔离的命令面板索引；业务搜索不得索引 Token 明文、凭据、完整票码或原始协议，管理员搜索不得索引任何业务数据。首期先做快捷导航和订单号精确搜索。

## 9. 视觉系统

### 9.1 方向

“票务运营台”：80% 专业运营、20% 电影票务身份。避免通用 SaaS 蓝白模板，也避免海报、霓虹和黑金影院宣传风。标志性元素只有“票根旅程”，用于自动化能力链、订单阶段轨迹和订单详情时间线；导航、设置和表单保持安静。

### 9.2 颜色

| Token | Hex | 用途 |
| --- | --- | --- |
| Screen White | `#F7F8F5` | 页面背景 |
| Paper White | `#FFFFFF` | 面板与票面 |
| Projection Indigo | `#25324A` | 品牌、主操作、自动处理中 |
| Reel Orange | `#E56B3F` | 当前动作、关键金额 |
| Ticket Green | `#18866B` | 完成、出票、发货成功 |
| Warning Amber | `#C58A24` | 等待外部 |
| Stop Red | `#C6473D` | 需要用户决定 |
| Carbon | `#20242B` | 文字、结果未知基底 |
| Hairline | `#DDE1DC` | 边界与票根虚线 |

结果未知使用 Carbon 与 Warning Amber 的封签语言，不用普通错误红。

### 9.3 字体

- 页面大标题、产品名和电影名：`Source Han Serif SC` / `Noto Serif SC`，克制使用。
- 正文、按钮、表格和说明：`Inter` + `Noto Sans SC`。
- 金额、时间、订单号和诊断编号：`IBM Plex Mono` + 中文无衬线回退。

若部署不允许网络字体，随构建自托管必要字重或使用明确系统回退，不在运行时依赖外部 CDN。

### 9.4 票根旅程

- 已完成：实心打孔；
- 当前自动阶段：缓慢呼吸描边；
- 等待外部：空心打孔；
- 人工任务：红色缺口标记；
- 结果未知：黑黄封签，明确“禁止自动重试”。

动效只用于当前阶段、新任务一次进入和接单闸门切换，并尊重 `prefers-reduced-motion`。首版只做高质量亮色主题；CSS 从一开始使用语义变量，为后续夜间运营主题预留。

## 10. 扩展 Popup

Popup 首屏先呈现插件激活状态。未激活只能配置后端地址、输入审批通过的 Token 并点击“激活”，不能执行自动化。激活后自动恢复会话，并显示：

```text
影票小店 A
自动化就绪 · 正常接单

后端连接   在线
闲鱼页面   已连接
当前账号   已匹配
执行授权   有效至 2026-12-31

[停止接单] [打开控制台]
```

复杂订单处理、账号接管、规则编辑和诊断回到 Web 控制台。Popup 不复制控制台，也不提供远程业务副作用按钮。

## 11. 现有实现差距

以下不是视觉换肤可以解决的问题：

- 当前控制台订单页只查询本地出票订单，需新增 Bearer 鉴权的闲鱼订单旅程 API。
- `XianyuSellerAccount` 目前只是快照，需提升为稳定经营账号并承载配置、接单状态和统计归属。
- `XianyuPlatformOrder` 需显式引用经营账号、上游账号、配置版本、任务与决策。
- 当前 Token 与 installation ID 一对一永久绑定，需改为账号执行授权与 fenced session 模型。
- heartbeat 写入 `ONLINE` 但没有可靠离线判定，需 WebSocket presence 与超时状态投影。
- 当前通用手动状态接口需被任务特定决策 API 替换。
- 当前管理员跨用户订单 API 违反已确认隐私边界。
- 当前话术是 JSON 编辑，定价配置缺少草稿/发布版本和试算。
- 当前控制台没有营业时间、停止时段回复幂等、恢复任务、订单任务、通知和统计读模型。

## 12. 无障碍与响应式

- 所有状态同时使用文字、形状和颜色，不只靠颜色。
- 键盘焦点清晰；命令面板、抽屉、确认面板满足焦点管理。
- 表格在手机端改为任务卡，不横向压缩关键证据。
- 危险操作显示影响而不是仅显示“确认吗”；按钮文案与结果通知使用同一动词。
- 动效可关闭；金额和编号支持复制但票码默认遮挡。

## 13. 非目标

首版不做：暗色主题、复杂 BI、预测、排行榜、短信/邮件、法定节假日自动日历、无限营业时段、管理员业务代操作、自动切换备用良票账号、按页面猜测旧动作、结果未知自动重试。
