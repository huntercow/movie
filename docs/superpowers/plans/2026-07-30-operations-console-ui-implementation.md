# 票务自动经营控制台实施计划

**目标：** 将现有资源型控制台重构为业务用户优先的自动经营工作台，并以真实后端状态完成从接入、接单、完整订单旅程到例外处理的纵向闭环。

**产品需求：** `docs/prd/2026-07-30-ticket-automation-platform-v1-prd.md`

**前置规格：** `docs/superpowers/specs/2026-07-30-operations-console-ui-design.md`

**交付原则：** 先完成真实可用的纵向切片，不先平均美化全部旧页面；所有协议继续 Fail Fast，不使用假数据或兼容猜测；数据库只新增连续 Flyway 迁移；管理员与业务用户数据边界由后端强制。

## Phase 0：合同与安全边界

1. 删除或封闭管理员跨用户业务订单接口，并增加管理员无法查询报价、订单、闲鱼账号和票码的安全测试。
2. 将 Token 审批从“设置到期即批准”改为显式批准/拒绝；增加 `REJECTED` 终态、审批期限和治理审计。
3. 更新 OpenAPI、部署文档和控制台合同；管理员 schema 不包含业务字段。
4. 为业务用户新增 `/api/v1/app/xianyu/**` 查询与决策路径，全部绑定当前 `userId`；插件接口继续使用插件 Token 与执行代次。

**验收：** 管理员 API、UI、搜索与通知无法读取任何业务数据；业务用户不能跨账号范围；旧插件协议在明确迁移版本前不会得到伪造兼容。

## Phase 1：稳定经营账号与执行授权

1. 将闲鱼经营账号建模为稳定用户范围实体，唯一键至少包含 `userId + sellerUserId`，并为历史订单迁移明确账号引用。
2. 增加 Execution Authorization：一个闲鱼经营账号最多一个当前执行 Token；有效空闲 Token 可重新分配。
3. 增加 server-issued generation，所有插件业务请求携带并校验代次；接管时原子替换，旧执行者立即失效。
4. 建立插件到后端的 WebSocket：严格握手、presence、能力报告、配置刷新与会话替换；HTTP heartbeat 保留为最后活动记录。
5. 建立控制台实时订阅，只推送当前业务用户的结构化状态；断线时展示“实时更新中断”，不伪装插件离线。

**测试：** 多用户隔离、并发接管、旧代次拒绝、Token 到期/吊销/用户停用、断线重连、未知消息拒绝、敏感字段不入日志。

## Phase 2：接单状态与完整就绪链

1. 建立 Order Intake 状态、停止原因、Closed-Intake Period 和会话回复幂等记录。
2. 实现营业时间：用户时区、每天最多两个时段、跨夜、重叠拒绝、手动停止优先。
3. 计算 Automation Readiness：接待、报价、验款、出票、发货，以及执行授权、页面、账号、上游、队列等证据。
4. 关键能力故障触发 Readiness Stop；恢复后只能由业务用户确认恢复。
5. 确保 Accepted Order 在停止接单后继续验款、出票和发货；新截图不 OCR、不报价，非订单会话只回复一次下班话术。

**测试：** 停止边界、恢复确认、跨夜时间、并发会话幂等、已接受订单续跑、关键能力矩阵、结果未知不重放。

## Phase 3：订单旅程、任务与决策

1. 建立当前用户的订单旅程 read model，将报价、改价、实付、出票、发货、配置版本和证据映射为互斥阶段。
2. 建立 Order Task 与 Recovery Task，定义任务类型、优先级、SLA、合法动作、暂缓和解决证据。
3. 用任务特定决策 API 替换通用手动状态更新；迁移现有 `NEED_MANUAL` 数据到明确任务或隔离队列。
4. 建立站内通知，严格区分已读与已解决；同一事件去重并链接任务。
5. 建立已收款、已完成、预计利润和已实现利润的统计投影。

**测试：** 每类任务动作白名单、金额/提交/发货结果未知、决策审计、暂缓到期、通知去重、统计时区与退款口径。

## Phase 4：核心 Web UI 纵向切片

1. 重写应用壳：五个业务入口、管理员三入口、账号范围选择、接单动作、通知与命令入口。
2. 建立语义化设计 Token、字体、自托管策略、票根旅程组件和响应式规范。
3. 实现可恢复首次启用向导，全部步骤读取真实后端状态。
4. 实现“今日”：就绪链、恢复任务、订单任务、进行中订单和轻量经营指标。
5. 实现订单中心和订单详情“时间线 + 决策面板”，移动端改为任务卡与上下结构。
6. 实现自动化账号运行卡、执行 Token 更换、实时状态与诊断。

**验收：** 一个新业务用户可以完成安全接入；一个已有用户可以停止/恢复接单、查看完整订单旅程并解决一个任务；所有页面不读取插件 Token 明文，不使用模拟指标。

## Phase 5：经营设置与管理员治理 UI

1. 实现营业时间与停止接单话术编辑。
2. 实现可视化话术规则、受控变量、预览、默认配置和账号覆盖；JSON 仅高级导入导出。
3. 实现定价草稿、试算、边界校验、发布和历史版本引用。
4. 实现多个良票账号及显式账号绑定；变更只影响新 Accepted Order。
5. 实现管理员用户主档、待审批队列、批准期限、拒绝和用户治理审计。

**验收：** 配置发布不修改历史订单；未知变量和无效定价立即失败；管理员页面不出现闲鱼账号或业务字段。

## Phase 6：扩展 Popup 与收尾

1. 重设计 Popup：显式激活、自动恢复、当前账号、就绪链、接单状态和打开控制台。
2. 浏览器系统通知消费后端业务通知，但不重复生成业务事件。
3. 将 `xianyu-manual.html` 能力迁入订单详情后删除旧入口。
4. 增加角色隔离的命令面板，首期支持快捷导航和精确订单号搜索。
5. 构建 `web` 并同步 `src/main/resources/static/console/`，构建扩展并确认 Manifest 产物。

## Phase 7：后续增强

- 完整经营数据页与账号对比；
- 微信业务通知渠道；
- 话术与定价版本回滚；
- 夜间运营主题；
- 法定节假日和临时营业例外；
- 更丰富的脱敏诊断包。

## 全量验证

每个 Phase 运行最小充分测试，最终必须运行：

```bash
mvn test
cd web && npm run build
cd ../extension && npm test && npm run typecheck && npm run build
git diff --check
```

还需进行桌面、平板和手机视口的键盘、焦点、减弱动画、错误态、空态和长文本检查；真实环境先在停止接单与自动履约关闭状态下演练，未经用户明确授权不执行真实下单、支付或发货。
