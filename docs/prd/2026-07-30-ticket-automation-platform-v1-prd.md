## 1. 产品概述

票务自动经营平台帮助业务用户通过闲鱼完成电影票图片识别、报价、改价、实付验证、上游出票、票码发送和闲鱼发货。V1 将现有按后端资源拆分的管理后台重构为一个“自动运行、例外由用户决定”的经营系统。

产品的核心承诺是：

> 系统在完整证据与安全前提下自动完成订单旅程；无法安全决定时停止相关自动动作，并将明确任务交给业务用户。

V1 不只是 UI 换肤。它同时确立稳定的闲鱼经营账号、可替换执行授权、实时连接、接单状态、完整订单旅程、任务化人工决策、配置版本和管理员隐私边界。

## 2. 问题陈述

当前系统已经具备主要业务能力，但在产品层存在以下问题：

1. 控制台按报价、本地订单、Token、良票账号和话术等技术资源拆分，业务用户无法在一个地方理解完整订单旅程。
2. 当前订单页以本地出票订单为主，不能统一呈现闲鱼订单、改价、实付验证、出票与发货。
3. heartbeat 状态不能可靠证明插件实时在线，更不能证明完整自动化可用。
4. Token、设备快照和闲鱼账号的职责不清晰，换 Token 或设备会影响在线判断，并可能割裂统计理解。
5. 人工处理允许通用状态修改，不能根据异常类型约束合法动作和证据。
6. 管理员存在跨用户业务查询能力，与“只治理用户和授权”的角色边界冲突。
7. 话术和定价配置偏技术化，缺少可视化编辑、试算、发布版本与历史可解释性。
8. 缺少停止接单、营业时间、恢复任务、订单任务、统一通知和稳定统计口径。
9. 现有视觉是通用蓝白管理后台，不能体现票务经营身份，也没有用视觉结构表达业务进度和风险。

## 3. 产品目标

### 3.1 业务目标

- 让业务用户一眼判断自动化是否完整就绪、当前是否接单以及为何停止。
- 让订单从报价到闲鱼发货形成一条可解释、可审计的业务旅程。
- 让系统自动处理正常订单，只把需要判断的例外交给业务用户。
- 在换设备、换 Token、插件断线和账号接管时保持订单归属、统计和幂等安全。
- 让业务用户可安全管理营业时间、话术、定价与良票账号绑定。
- 让管理员完成用户和授权治理，同时从技术上无法访问用户业务。

### 3.2 体验目标

- 首页优先展示恢复任务和订单任务，而不是资源总数。
- 用户能在一个订单详情中理解发生了什么、当前证据是什么、下一步会发生什么。
- 有业务后果的操作展示影响范围和证据，不使用通用状态下拉框。
- 桌面端支持完整运营；移动端支持查看和单项紧急处理。
- 形成区别于通用后台的“票务运营台”视觉身份。

### 3.3 安全目标

- 未通过金额验证的订单绝不进入自动上游履约。
- 外部结果未知时绝不自动重试。
- 同一闲鱼经营账号同一时刻只有一个有效执行授权。
- 管理员不能访问业务数据，任何搜索、通知和 API 都不得绕过该边界。
- 停止接单不破坏已接受订单，也不产生重复下单或重复发货。

## 4. 非目标

V1 不包含：

- 完整经营 BI、预测、排行榜和复杂交叉分析；
- 微信业务通知、短信和邮件；
- 全局命令面板；
- 话术或定价的一键版本回滚；
- 法定节假日自动日历和无限营业时段；
- 暗色或夜间主题；
- 批量退款、关闭、重下、发货、解决任务或显示票码；
- 管理员代业务用户处理订单；
- 自动选择或切换备用良票账号；
- 保存完整原始外部协议 payload；
- 结果未知后的自动重试；
- 为旧扩展维持双执行合同。

## 5. 角色与权限

### 5.1 业务用户

业务用户是第一核心角色，只能管理自己的：

- 闲鱼经营账号；
- 订单、报价、任务、通知和经营统计；
- 插件与机器人 Token；
- 执行授权和运行客户端；
- 良票账号与绑定；
- 营业时间、接单状态、话术和定价；
- 账号安全。

业务用户创建 Token，并且仅在创建成功后一次性看到 Token 明文。

### 5.2 管理员

管理员只能：

- 创建、停用和恢复业务用户；
- 重置业务用户初始密码；
- 查看 Token 前缀、类型、申请时间、审批状态和有效期；
- 批准并设置期限、拒绝、续期或吊销 Token；
- 查看治理审计。

管理员不能查看、搜索或通过 API 获取：

- Token 明文；
- 闲鱼账号 ID 或昵称；
- 买家与会话；
- 报价、订单、金额和利润；
- 电影、场次与座位；
- 票码；
- 良票用户名或上游业务订单；
- 业务任务、业务通知和经营统计。

停用业务用户时，系统必须撤销其 Web 会话和执行授权，并停止其所有闲鱼账号接单，但不删除业务数据，也不向管理员开放业务数据。

## 6. V1 范围

V1 必须形成可真实运行的纵向闭环。以下全部属于 V1：

- 管理员与业务数据彻底隔离；
- Token 创建、批准、拒绝、续期与吊销；
- 稳定闲鱼经营账号；
- 单账号单执行授权与安全接管；
- 插件到后端 WebSocket 实时连接；
- 自动化就绪能力链；
- 停止接单、营业时间和停止时段单次回复；
- 可恢复首次启用向导；
- “今日”运营收件箱；
- 闲鱼订单中心与完整订单旅程；
- 恢复任务、订单任务与任务特定人工决策；
- 站内通知和浏览器系统通知；
- 可视化话术配置；
- 版本化定价与实时试算；
- 多良票账号与显式绑定；
- Chrome 扩展 Popup 重设计；
- 旧人工处理页下线；
- 首页轻量经营指标。

## 7. 领域关系

```text
业务用户
├── 闲鱼经营账号
│   ├── 永久拥有订单、统计与账号级配置
│   ├── 当前接单状态与营业时间
│   ├── 一个当前执行授权
│   └── 一个显式良票账号绑定
├── 默认话术与定价配置
├── 良票账号
└── 插件 / 机器人 Token

执行授权
├── 由一个已审批且有效的插件 Token 提供
├── 同一账号同时只有一个
└── 可被新 Token 原子替换，不改变账号历史

闲鱼平台订单
├── 永久归属一个闲鱼经营账号
├── 关联报价与发布配置版本
├── 关联一个固化的良票账号
├── 关联本地出票订单与上游订单
├── 包含 Delivery Attempt
└── 产生零个或多个任务与人工决策
```

订单和统计归属闲鱼经营账号，不归属 Token、设备或插件会话。有效且当前空闲的 Token 可授权另一个闲鱼账号。

## 8. 信息架构

### 8.1 业务用户导航

```text
今日
订单中心
经营数据
自动化
经营设置
```

V1 的“经营数据”只包含轻量指标说明和后续能力占位，不实现完整分析工作台。账号安全进入用户菜单。顶栏包含闲鱼账号范围、接单状态、通知入口和用户菜单。

### 8.2 管理员导航

```text
待审批
用户与授权
治理审计
```

管理员没有业务工作区入口。

## 9. 核心用户旅程

### 9.1 新用户首次启用

```text
创建 Token
→ 等待管理员批准并设置期限
→ 安装插件并显式激活
→ 识别闲鱼经营账号
→ 配置并绑定良票账号
→ 设置接单规则与营业时间
→ 发布话术和定价
→ 自动履约关闭下完成安全演练
→ 所有能力证据通过
→ 用户确认开始接单
```

向导可中断恢复，每一步读取真实后端状态。新增第二个闲鱼账号使用精简流程并可继承用户默认配置。

### 9.2 正常订单旅程

```text
收到图片
→ OCR 与报价
→ 待付款订单登记（Accepted Order 截止点）
→ 闲鱼改价
→ 收到付款信号
→ 查询官方订单详情
→ 三方金额验证
→ 创建并续跑本地 / 上游订单
→ 出票
→ 创建一次性 Delivery Attempt
→ 发送票码与闲鱼发货
→ 发货成功，订单完成
```

### 9.3 停止接单

业务用户可停止全部账号或当前账号接单。停止后：

- 不处理新截图、不调用 OCR、不生成新报价；
- 已登记待付款订单继续验款、出票与发货；
- 有未完成 Accepted Order 的会话继续订单阶段回复；
- 其他会话在一个连续停止接单时段内最多收到一次下班回复；
- 已开始且结果未知的外部动作不重放。

### 9.4 执行授权接管

新 Token 接管已有闲鱼经营账号时：

- 后端原子替换执行授权并提升 generation；
- 旧 Token 对该账号的执行权限立即失效；
- 旧插件连接被关闭，即使未收到下线消息，其旧代次请求也被拒绝；
- 账号历史、统计、营业时间和配置保持不变；
- 安全订单继续；
- 外部结果未知的具体订单进入最高优先级任务；
- 接管操作记录审计。

### 9.5 异常处理

用户从通知或今日页进入 Order Task，查看订单时间线、证据、影响与合法动作。查看通知只改变已读状态，不解决任务。完成合法动作或得到恢复证据后，任务才解决。

## 10. 功能需求

### FR-01 闲鱼经营账号

- 系统必须以 `userId + sellerUserId` 唯一识别闲鱼经营账号。
- 闲鱼经营账号必须是订单、统计、接单状态、营业时间、账号级配置和上游绑定的稳定主体。
- Token、设备和当前插件快照不得成为订单统计主体。
- 全部账号与单账号视角必须严格按当前业务用户过滤。

### FR-02 Token 生命周期与审批

- 业务用户创建 Token，明文只返回一次，后端只保存不可逆摘要。
- 管理员批准时必须选择 30、90、180 天或自定义未来期限。
- 管理员可拒绝申请；拒绝为终态，不能再次批准，用户需要创建新申请。
- 管理员可续期或吊销；吊销不可恢复。
- V1 不设置 Token 数量硬配额，但审批页显示同类有效数量与近期申请频率。
- 管理员永远看不到 Token 明文和 Token 对应的闲鱼经营账号。

### FR-03 执行授权与插件会话

- 一个闲鱼经营账号同时只能有一个 Execution Authorization。
- 一个已审批、未到期、未吊销且当前空闲的插件 Token 可成为执行授权。
- 新授权替换旧授权时必须原子提升 generation。
- 所有插件业务请求和 WebSocket 消息必须校验 Token、闲鱼账号、当前 generation 和用户归属。
- 插件首次显式激活，之后可自动恢复会话；无有效会话不能执行自动化。
- installation ID 用于设备识别和审计，不拥有订单历史。

### FR-04 实时连接

- 插件必须与后端建立鉴权 WebSocket，报告 presence、页面连接、当前闲鱼账号和结构化能力状态。
- 后端必须在连接断开或被替换时实时更新 presence。
- HTTP heartbeat 保留最后活动时间，但不得单独证明在线或 Automation Ready。
- Web 控制台只订阅当前业务用户的数据；控制台实时通道断开只显示“实时更新中断”。
- 控制面只允许请求重新上报、刷新发布配置、停止或恢复接单等安全操作。
- WebSocket 不允许远程触发改价、下单、付款验证、发送票码或发货。
- 未知消息类型、缺失字段、错误代次或错误归属必须立即失败。

### FR-05 Automation Readiness

- 系统必须显示一个总状态和五段能力：接待、报价、验款、出票、发货。
- 底层证据至少包括执行授权、插件连接、闲鱼页面、账号匹配、OCR/报价、良票账号、凭据解密、任务队列和发货能力。
- 任一完成完整旅程所需的关键能力不可用时，系统必须触发 Readiness Stop。
- 能力恢复后只显示“可以恢复”，不得自动恢复接单。
- 插件在线但页面、账号、良票或发货不可用时，不得显示为自动化就绪。

### FR-06 接单状态与营业时间

- 用户可按全部账号或单账号停止/恢复接单。
- 停止操作必须展示作用范围、停止后的行为、已接受订单数量和可选原因。
- 恢复前必须执行完整就绪检查。
- 用户可按时区设置每周营业时间，每天最多两个时段，允许跨夜，禁止重叠。
- 优先级为：管理员停用用户 > Readiness Stop / 用户手动停止 > 营业时间 > 正常接单。
- Readiness Stop 恢复后需要用户确认；营业时间正常开门可按计划自动恢复，但若仍存在更高优先级停止原因则保持停止。

### FR-07 停止时段回复

- 停止接单后，系统继续普通聊天，但不处理新图片报价。
- 无未完成 Accepted Order 的会话，每个 Closed-Intake Period 最多发送一次下班回复。
- 幂等记录必须由后端持久化，刷新页面、插件重连或换设备不得重复发送。
- Accepted Order 会话继续按订单阶段正常回复。

### FR-08 今日运营收件箱

今日页必须按顺序展示：

1. 自动化就绪与接单状态；
2. 恢复任务；
3. 订单任务；
4. 正在处理的订单阶段；
5. 今日已收款、已完成、已实现利润和自动完成率。

首页任务只提供“查看并处理”，不直接执行退款、关闭、重下或发货。

### FR-09 订单中心

- 订单中心必须以 Xianyu Platform Order 为主对象。
- 列表业务筛选为：全部、需要处理、待付款、验款、出票中、待发货、已完成。
- 默认排序为：高风险任务、即将超时、最近更新的进行中订单、已完成订单。
- 列表显示闲鱼账号、电影与场次、买家脱敏标识、金额、当前阶段、下一步和更新时间。
- 报价记录作为次级视图，本地出票订单作为订单详情中的一个阶段。
- 内部枚举和技术错误不作为列表主语言。

### FR-10 订单详情

- 订单详情必须包含摘要、票根旅程、当前决策面板和折叠诊断区。
- 时间线统一展示报价、待付款登记、改价、付款证据、金额验证、本地订单、上游订单、出票、Delivery Attempt、发货和人工决策。
- 每个节点显示来源、金额或状态、时间和证据完整性。
- 决策面板只显示当前任务允许的动作。
- 诊断区可展示内部状态和诊断编号，但不得展示敏感原始响应。

### FR-11 任务与通知

- Recovery Task 与 Order Task 必须分开。
- 任务状态至少包含待处理、处理中、已解决；通知状态至少包含未读、已读。
- 通知已读不得解决任务。
- 同一业务事件只产生一条可更新通知。
- 任务可按规则暂缓，但仍未解决；到期或更早风险期限时返回主队列。
- 结果未知任务不可暂缓。
- V1 支持站内通知和活动插件浏览器通知。
- 管理员只接收治理与 Token 审批通知。

### FR-12 人工决策

- 系统必须取消任意手动修改订单状态。
- 每个任务类型必须定义合法动作白名单。
- Manual Decision 必须记录动作、操作人、时间、必填说明和相关结构化证据。
- V1 不允许批量业务决策。
- 超时只升级优先级和通知，不自动退款、关闭、重下或发货。

### FR-13 话术配置

- 提供普通接待、订单阶段、停止接单和异常提示的可视化编辑。
- 使用受控变量插入；未知变量、错误类型或缺失必需模板必须保存失败。
- 支持买家视角预览。
- JSON 仅作为高级导入/导出，不是主编辑方式。
- 支持用户默认配置和账号级显式覆盖。
- 发布版本不可变，并被相关消息或订单引用。

### FR-14 定价配置

- 支持草稿、实时试算、边界样例校验和发布。
- 发布前展示相对当前版本的变化和影响范围。
- 无利润、超票面价、金额精度错误或违反安全边界的规则不得发布。
- 发布只影响新报价；历史报价和订单固定引用原版本。
- 支持用户默认策略和账号级覆盖。

### FR-15 良票账号与绑定

- 业务用户可配置多个良票账号，凭据使用现有加密机制，密码不回显。
- 多个闲鱼账号可共享一个良票账号。
- 每个闲鱼账号必须显式绑定一个良票账号，系统不得运行时猜测或自动切换。
- Accepted Order 创建时固定良票账号引用，后续改绑只影响新订单。
- 良票账号不可用时，所有绑定账号触发 Readiness Stop。

### FR-16 管理员治理

- 管理员首页优先展示待审批 Token、即将到期授权和用户治理任务。
- 用户主档聚合账号状态、最近登录、密码状态、Token 前缀、审批状态、有效期和治理审计。
- 用户主档不得出现闲鱼账号、订单、金额、利润、票码或良票账号。
- 所有管理员敏感动作必须写治理审计。

### FR-17 扩展 Popup

- 未激活插件只能配置后端地址、输入 Token 并执行激活，不能运行自动化。
- 激活后显示闲鱼经营账号、自动化就绪、接单状态、后端连接、页面连接、账号匹配和授权到期时间。
- 提供停止接单和打开控制台；复杂任务、账号接管和规则编辑回到 Web 控制台。
- 插件接收会话替换、通知和配置刷新，但不得自行推断或补做旧外部动作。

### FR-18 敏感数据

- 票码默认脱敏。
- 完整票码必须通过单独 Sensitive Reveal 获取，短时显示并记录审计。
- 显示和复制分别记录业务用户、订单、时间和动作。
- 列表、搜索、通知、日志、导出和管理员接口永不包含完整票码。
- 插件发货使用一次性 Delivery Attempt 授权，不复用控制台显示接口。
- 原始 Token、密码、Cookie、完整协议响应和完整图片 Base64 不得记录。

## 11. 订单任务动作矩阵

| 任务类型 | 优先级 / SLA | 允许动作 | 禁止动作 |
| --- | --- | --- | --- |
| 上游提交结果未知 | 立即最高；不可暂缓 | 核对“找到上游订单”或“确认不存在”；确认不存在后单独授权一次新建 | 直接重下、覆盖未知记录 |
| 发货结果未知 | 立即最高；不可暂缓 | 核对已发货或未发货；未发货后单独创建新 Delivery Attempt 或记录人工发货 | 直接自动重发、覆盖旧 attempt |
| 疑似重复外部动作 | 立即最高；不可暂缓 | 人工核对并记录关联证据 | 再次执行外部动作 |
| 已收款但无法创建本地订单 | 5 分钟；最多暂缓一次且不超过 10 分钟 | 修复后创建；退款；关闭 | 跳过金额证据 |
| 已出票但无法自动发货 | 5 分钟；最多暂缓一次且不超过 10 分钟 | 修复后新建明确 attempt；记录人工发货；退款 | 使用未知 attempt 重放 |
| 实付金额不一致 | 5 分钟；最多暂缓一次且不超过 10 分钟 | 标记已退款；关闭订单 | 按实际金额强制出票、人工改金额 |
| 出票明确失败 | 30 分钟 | 已知上游订单则续跑；明确未创建则确认新 attempt；退款；关闭 | 不区分结果就“重试” |
| 良票账号失效且有 Accepted Order | 30 分钟 | 修复账号；保持任务直到证据恢复 | 自动切备用账号 |
| 插件断线且有未完成订单 | 30 分钟 | 恢复执行授权或接管；核对未知动作 | 由新插件猜测补做 |
| 非关键配置问题 | 营业结束前 | 修复配置；按期限暂缓 | 伪造已解决 |
| Token 即将到期 | 营业结束前 | 申请管理员续期；更换已审批执行 Token | 使用过期授权 |

### 11.1 上游提交 Reconciliation

找到上游订单时必填：`upstreamOrderNo`、可获得时的 `upstreamOrderId`、上游状态和说明。后端校验不与其他订单冲突后建立关联，只续跑已知订单。

确认不存在时必填：核对时间范围、使用的良票账号、核对时间和说明。确认本身不自动重下，只开放一次独立的新建确认，并保留原未知记录。

### 11.2 发货 Reconciliation

确认已发货或未发货时必填：闲鱼订单当前状态、核对时间和说明。确认已发货后旧 attempt 标记为人工核实成功并永不重放。确认未发货后，用户可单独创建新 Delivery Attempt 或记录人工发货；新 attempt 再次未知时创建新的最高优先级任务。

### 11.3 金额不一致

V1 绝不允许覆盖报价、改价或实付金额继续出票。若怀疑协议解析错误，应修复协议并重新获取官方订单详情，而不是人工填写金额。补款、部分退款和差额继续履约不在 V1。

## 12. 统计口径与成功指标

### 12.1 经营口径

- 已收款：实付金额验证通过，按验证时间统计。
- 已完成：闲鱼发货成功，按发货时间统计。
- 预计利润：报价时计算。
- 已实现利润：发货成功后计入；退款和发货结果未知不计入。
- 自动完成：已收款订单在没有 Manual Decision 的情况下成功发货。
- 单账号按账号时区统计；全部账号按业务用户默认时区统计。

### 12.2 V1 首月目标

| 指标 | 目标 | 口径 |
| --- | --- | --- |
| 自动完成率 | `>= 90%` | 自动完成订单 / 所有已收款订单；任何排除项必须单列 |
| 营业时段自动化可用率 | `>= 99%` | Automation Ready 分钟 / 应营业分钟；用户主动停止和非营业时间不进分母，Readiness Stop 计不可用 |
| 新用户启用时长 | 中位数 `<= 15 分钟` | Token 已审批到 Automation Ready |
| 高风险通知延迟 | `<= 10 秒` | 任务创建到站内 / 插件通知生成 |
| 能力状态可见延迟 | `<= 5 秒` | 插件状态变化到控制台可见 |

### 12.3 安全护栏

以下目标全部为 `0`：

- 重复上游订单；
- 重复发货外部动作；
- 管理员读取业务数据事件；
- 未经金额验证进入上游履约的订单；
- 结果未知后的自动重试；
- 旧 execution generation 成功执行请求。

## 14. 数据保留与隐私

| 数据 | 保留策略 |
| --- | --- |
| 订单、金额证据与配置版本 | 长期保留；V1 不自动删除 |
| Manual Decision、Reconciliation、Delivery Attempt | 长期保留 |
| 治理审计 | 至少 2 年 |
| 业务通知 | 90 天后归档，1 年后删除展示记录 |
| WebSocket 当前 presence | 只保留当前状态 |
| 结构化连接事件 | 30 天 |
| 诊断错误摘要 | 90 天 |
| 完整外部协议 payload | 不保存 |

V1 不提供删除用户及全部业务数据。停用用户不删除数据。未来归档或删除政策不得破坏订单证据链、统计和审计引用。

## 15. 迁移要求

- 仅当 `userId + sellerUserId` 明确且唯一时，历史订单才能自动归属闲鱼经营账号。
- 不得因为用户只有一个已知账号、最近插件快照、nickname、chatId 或 Token 而推断归属。
- 无法唯一归属的订单进入 Unassigned Historical Order 队列。
- 未归属订单不参与账号统计、不触发自动履约，由业务用户查看结构化证据后记录审计归属。
- 旧 Token / installation 绑定不自动转换为 Execution Authorization，用户必须显式激活。
- 迁移期间默认停止接单；用户逐账号完成 Readiness Journey 后确认恢复。
- 旧人工页面在新订单任务可完整访问前只读保留，之后下线。
- 所有数据库变更使用连续新 Flyway 迁移，不修改既有迁移。

## 16. 发布与回退

### 16.1 灰度发布

```text
部署迁移与新 API
→ 平台保持新接单关闭
→ 发布新控制台和扩展
→ 选择测试业务用户
→ 完成历史归属、执行授权和安全演练
→ 用户逐账号确认接单
→ 观察指标与护栏
→ 扩大下一批用户
```

- 旧扩展不支持 generation 时，后端明确拒绝激活。
- 不保留旧执行合同的双写兼容。
- 灰度开关只控制是否进入新启用旅程，不放宽业务规则。
- 每批先在自动履约关闭状态演练，未经用户确认不真实接单。

### 16.2 回退

- 回退首先停止接单。
- 可以回退 UI 展示，但不得回滚已执行数据库迁移。
- 不得恢复旧自动化写路径或通用手动状态接口。
- 已产生的新证据、任务、attempt 和决策必须保留。

## 17. GA 门槛与签收

### 17.1 管理员签收

- 用户与业务数据隔离；
- Token 批准、拒绝、到期、续期与吊销；
- 治理审计；
- WebSocket 容量；
- 部署、迁移与回退准备。

### 17.2 业务用户签收

- 闲鱼账号归属；
- 插件执行授权；
- 营业时间和话术；
- 定价试算与发布；
- 良票账号绑定；
- 自动履约关闭下的安全演练；
- 明确确认真实接单。

### 17.3 全平台 GA

全部满足后才能 GA：

- 至少 2 个业务用户或 3 个闲鱼经营账号完成灰度；若实际只有 1 个业务用户，则至少 2 个账号；
- 连续 7 天无任何安全护栏事件；
- 自动完成率 `>= 90%`；
- 营业时段自动化可用率 `>= 99%`；
- 所有最高优先级任务都在 SLA 内得到首次有效处理；
- 没有未解释的数据迁移差异；
- 所有旧自动化写入口已关闭。

主要 Token：

- Paper White `#FFFFFF`
- Projection Indigo `#25324A`
- Reel Orange `#E56B3F`
- Ticket Green `#18866B`
- Warning Amber `#C58A24`
- Stop Red `#C6473D`
- Carbon `#20242B`

结果未知使用 Carbon + Warning Amber 封签，不用普通错误红。

### 18.2 交互

- 首页只发现和分流，有业务后果的动作进入详情。
- 停止接单展示影响，不使用裸开关。
- 恢复接单展示完整就绪检查。
- 订单详情使用“时间线 + 决策面板”。

- 桌面优先；移动端使用任务卡和上下结构。

- 所有错误、空态和禁用状态说明下一步。

## 19. 验收场景

V1 至少通过以下端到端场景：

1. 新业务用户创建 Token，管理员批准，插件激活，完成向导并开始接单。
2. 管理员拒绝 Token 后无法再次批准，用户重新创建申请。
3. 同一闲鱼账号由新 Token 接管，旧代次所有请求失败，历史统计不变。
4. 插件在线但良票失效时显示未就绪并自动停止接单。
5. 能力恢复后不会自动接单，用户确认后恢复。
6. 营业时间跨夜正确开关，手动停止优先。
7. 停止接单后新截图不 OCR、不报价，每会话每停止时段只回复一次。
8. 停止接单前已登记订单继续付款验证、出票和发货。
9. 正常订单完整走过报价、改价、验款、出票和发货时间线。
10. 金额不一致只能退款或关闭，不能强制出票。
11. 上游提交未知必须先 Reconciliation，再单独确认新 attempt。
12. 发货未知必须先核对，旧 attempt 永不重放。
13. 通知已读但任务仍待处理，任务解决后进入历史。
14. 结果未知任务不可暂缓，其他任务按 SLA 暂缓并重新出现。
15. 票码默认脱敏，显示和复制均审计，管理员无法获取。
16. 发布新定价或话术不改变历史订单引用。
17. 改绑良票账号只影响新 Accepted Order。
18. 历史订单无法唯一归属时进入隔离队列，不参与统计。
19. 管理员 API、UI、搜索和通知均无法读取业务数据。
20. 基线容量下列表、详情、通知和实时状态满足性能目标。

## 20. 依赖与风险

### 20.1 依赖

- 闲鱼页面账号识别与 WebSocket hook 的已确认协议；
- 良票账号与现有凭据加密能力；
- 持久任务队列和现有订单幂等键；
- Chrome Manifest V3 background 生命周期；
- MySQL/Flyway 连续迁移；
- WebSocket 在部署网络和反向代理中的支持。

### 20.2 主要风险与缓解

| 风险 | 缓解 |
| --- | --- |
| MV3 background 休眠导致连接中断 | 明确重连、generation 校验、heartbeat 最后活动时间，不把断线伪装在线 |
| 多节点后端中的 WebSocket 路由 | V1 明确部署拓扑；扩容前提供共享 presence / routing 方案 |
| 历史账号归属不完整 | 严格隔离，不使用 fallback 推断 |
| 接管过程中重复外部动作 | fenced generation、持久 attempt、未知结果任务 |
| UI 重构掩盖协议错误 | 所有 API 严格 decoder，未知状态立即失败 |
| 管理员权限残留 | 删除跨用户业务 API，增加负向安全测试 |
| 配置发布导致新订单风险 | 草稿、试算、边界测试、版本固化 |
| 任务过多造成告警疲劳 | 双队列、去重通知、风险 SLA、受约束暂缓 |

## 21. 需求追踪与变更规则

- 本 PRD 是 V1 产品范围、业务规则和验收基线。
- UI 细节以关联设计规格为准；技术拆分以实施计划为准。
- 若实现与 PRD 冲突，不得以兼容或 fallback 自行选择行为，必须回到产品决策。
- 影响管理员隐私边界、金额验证、外部动作幂等、订单归属、任务动作白名单或统计口径的变更，必须更新 PRD、领域词汇和相应 ADR。
- V1 后置项不得在未定义业务协议时以隐藏入口或实验 fallback 进入生产流程。

## 22. 未决事项

当前无阻塞 V1 进入实施的产品未决事项。多节点 WebSocket 路由的具体技术选型、字体自托管文件和页面组件拆分属于实施设计，不改变本 PRD 的产品合同。
