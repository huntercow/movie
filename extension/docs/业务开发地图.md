# 业务开发地图

本项目分为「浏览器插件」（src/）与「业务后端」（backend/）两部分。本文档是「收到闲鱼消息后，代码怎么走、改哪里」的地图。

## 总体架构

```
闲鱼 IM 页面 ←→ 浏览器插件（src/）←→ FastAPI 后端（backend/）←→ 良票上游
                    │                                      │
                    └── 页面侧动作（改价/取消）            └── OSS 上传 / OCR / 报价 / 下单 / 出票
```

- **插件**：拦截闲鱼 WebSocket 消息、识别事件、编排后台请求、页面侧 MTop 动作、发消息
- **后端**：业务状态机（订单 20→25→30→50/90/450）、良票对接、报价策略、话术配置下发、Web 管理页（/admin）
- **Web 管理页**：`backend/web/`（浏览器访问 `http://127.0.0.1:8000/admin/`），订单/报价策略/资金看板

## 识别消息类型（webhook 层）

`webhook/xianyuProtocol.ts` 的 `decodeXianyuPayload()` 按帧形状依次尝试：

| 帧特征 | 事件 | 业务去向 |
|---|---|---|
| 有 `code` 字段 | `ACK` 连接回执 | 无操作 |
| 只有数组键 `"1"` | `SESSION_SIGNAL` 会话上下线 | 无操作 |
| `needPush` 标准帧 | 按 contentType：1=文字、2=图片、26=交易卡、14=提示 | 文字→回复；图片→报价；卡片→改价/验款 |
| `extJson` 元数据 | `MESSAGE_UPDATE` 改价通知 | 显式忽略 |
| PNM 形状 | `PNM_STATUS` 已读标记 | 无操作 |
| 有 `orderId` | `ORDER_CONTEXT` | 记录买家映射 |
| 有 `redReminder` | 付款/待付款摘要 | → 改价/验款 |

帧形状不匹配任何分支 → 抛错 → `recordSocketFailure` 日志（页面 console）。

## 四条业务链路

### 1. 文字回复
```
买家文字 → decodeXianyuPayload → TEXT_MESSAGE
  → xianyuPageHook.handleTextMessage
  → handlers/replyAutomation.ts decideTextReply（关键词规则命中即回）
  → webhook/xianyuMessageSender.ts 发送
```

### 2. 选座截图报价（核心）
```
买家发图 → IMAGE_MESSAGE
  → xianyuPageHook.handleImageMessage → 发「正在识别」
  → request("QUOTE_IMAGE") → 后台 → 后端 /quote-image
      → 后端：下载截图 → OSS 上传 → 良票 OCR → 双通道报价（限价+一口价）
      → 定价 = 较高正价 + 加价（quote.py，0 价通道视为失败）
      → 派生订单 status 20（存 seats_image 选座截图）
  → 发「报价成功/失败」话术
```
日志：`[报价]`、`[良票]`、`[OSS]` 前缀，在 `backend/uvicorn.err.log`。

### 3. 待付款改价
```
WAITING_PAYMENT_CARD/SUMMARY → 后端 getWaitingPaymentOrder 查 status 20
  → 金额与报价不一致 → webhook/xianyuMtopExecutor.adjustPrice（页面侧改价）
  → 回写 status 25（含闲鱼订单号）→ 发「改价成功」话术
```

### 4. 已付款验款 + 出票 + 交付
```
PAID_CARD/SUMMARY → 后端查 status 25 订单 → 读闲鱼订单实际金额（分）对比
  → 一致：回写 status 30（后端触发良票下单+支付）
  → 出票轮询（10 秒）：getOrderDetail → 已出票→50 / 已退款→450
  → 交付：ticketDeliveryAutomation（票码话术/图片）→ 回写结算
  → 不一致/上游失败：发 cancel_ticket 话术 → 取消闲鱼订单 → 回写 status 90
```

## 常见改动点

| 想改什么 | 改哪里 |
|---|---|
| 话术模板/关键词规则 | 插件 manage 页（「话术模板」「关键词规则」区块编辑 → 写回后端） |
| 对买家售价（加价） | Web 管理页「报价策略」（固定加价/差价阈值/系数） |
| OSS 凭证 / 良票账号 | 后端环境变量（backend/config.py） |
| 报价流程逻辑 | `backend/quote.py` |
| 订单状态机 | `backend/orders.py` + `backend/main.py` |
| 消息类型判断 | `webhook/xianyuProtocol.ts` 的 `decodeXianyuPayload` |
| 新消息类型处理 | ① 解码器产出新事件 kind → ② `xianyuPageHook.handleSocketMessage` switch 加分支 → ③ handlers/ 写处理逻辑 |
| 自动回复判定 | `handlers/replyAutomation.ts` `decideTextReply` |
| 出票轮询节奏 | `handlers/ticketResultPoller.ts`（10 秒） |
| 后台消息路由 | `src/background.ts` 的 `handleMessage` switch |
| 管理页 UI | `backend/web/`（index.html + scripts/dashboard.js） |

## 调试日志怎么看

- **页面 console**（闲鱼页面 F12）：`[xianyu-ticket]` 前缀——注入状态、`✅` 业务动作、`websocket:message-failed` 解码失败
- **后端日志**：`backend/uvicorn.err.log`（业务日志：`[报价]`/`[良票]`/`[OSS]`/`[订单]`）、`backend/uvicorn.log`（HTTP 访问）
- **插件状态**：页面 `window.xianyuMovieTicketDebug.status()` 或 DOM 属性 `data-xianyu-movie-ticket-status`
- **Web 管理页**：`http://127.0.0.1:8000/admin/`（订单列表/报价策略/资金/系统）
